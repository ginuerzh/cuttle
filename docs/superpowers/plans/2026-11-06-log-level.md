# Runtime Log Level Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `log` config block and a small llm-gw-owned logger whose level changes at runtime via SIGHUP or an admin config save, while routing `llm-api-converter` debug output through the same handler.

**Architecture:** A new `internal/logging` package implements `core.Logger` with `log/slog` and a shared `slog.LevelVar`. `main` creates it from `config.log` and sets it as the global `slog` default; SIGHUP and admin config saves call `logging.Apply` to change the level in place. Format is fixed at startup.

**Tech Stack:** Go 1.26, `log/slog`, existing core logger interface, Viper-free YAML config.

**Spec:** `docs/superpowers/specs/2026-11-06-log-level-design.md`

## Global Constraints

- Do not modify `../x` or any sibling repository.
- Defaults remain `info` + `json`; configs without `log` behave as before.
- `log.level` changes take effect on SIGHUP and admin config save without restart.
- `log.format` is read at startup only; changing it at runtime logs a warning.
- `llm-api-converter` global `slog` must share the logger's level and format.
- Levels: `trace`, `debug`, `info`, `warn`, `error`, `fatal`.
- Formats: `json`, `text`.
- Config validation rejects unknown levels/formats.
- Commit after each completed task with its Implementation record.

## Review Focus

- Raising the level to `debug` must immediately show gateway and converter debug lines; lowering it must immediately hide them.
- `WithFields` children must use the same live level, not a snapshot.
- Invalid levels/formats must fail before the config is written.
- Existing configs without `log` must not change output.
- Admin `PUT /api/config` must apply the level before returning 204.
- A format change must not corrupt output or silently pretend to apply; it must warn about restart.
- Concurrent logs and level changes must not race (`-race`).

- [ ] **Step 3: Implement `internal/logging`**

Create `logging.go` with:

- `Logger` fields: root `*slog.Logger`, `level *slog.LevelVar`, `format string`, `args []any`.
- `New` calls `newLogger(level, format, os.Stderr)`.
- `newLogger` parses level/format, returns an error naming the invalid value; builds a `slog.Handler`:
  - JSON: `slog.NewJSONHandler(out, &slog.HandlerOptions{Level: levelVar, ReplaceAttr: replaceAttr})`
  - Text: `slog.NewTextHandler(...)`
- Custom trace level `-8` and fatal level `12`, `convertLevel`/`revertLevel` like `x/logger`.
- `replaceAttr` lowercases level names and formats `time` as `2006-01-02T15:04:05.000Z07:00` (matches the existing x logger).
- `WithFields` merges fields with last-write-wins (copy the `mergeArgs` behavior) and shares the same level var and root.
- Log methods filter through `LevelVar`; at `debug` or lower add a `caller` field using `runtime.Caller(3)`.
- `Fatal`/`Fatalf` call `os.Exit(1)` after logging.
- `SetLevel` parses and updates the shared `LevelVar`; `GetLevel`/`IsLevelEnabled` reflect it.
- `Format` returns the active format.
- `SetDefault` calls `slog.SetDefault(l.root)` so `llm-api-converter`'s `slog.Debug` uses the same handler and level.
- `Apply(l, level, format)` type-asserts `SetLevel(string) error` + `Format() string` (so Nop loggers are a no-op), calls `SetLevel`, logs `log level:` on failure, and warns `log.format changed to %q; restart required` when the format differs.
